### 1.3b 【装机冒烟新抓出的历史遗留 P1】WS 桥握手 4096B peek 截断 → 页内桥全灭

装机版（install-check）冒烟时系统性复现：**152 次连拒、页内桥全灭、phoneBridge 20s 超时**
——而 target/release 同一二进制偶发通过，差异纯由时序/cookie 组成决定。调试打印实证：

```
[ws] rejected cross-origin / rebinding handshake: len=4096 first="GET /ws HTTP/1.1"
     Origin: http://127.0.0.1:19873 Host: 127.0.0.1:19873
```

根因（**P2 时代遗留，非批次一回归**）：`handle_conn` 单段 `peek(4096)` + 「未见
`\r\n\r\n` 即判头部截断拒收」。浏览器 cookie 按域名不按端口隔离——内核在
127.0.0.1 设置的 dsh-auth JWT 会被带回**桥端口**的 WS 握手，Cookie 头一胖
（累计多枚 JWT/长 UA/扩展协商）握手头就超 4096B，peek 永远看不到终止符 →
桥 WS 被永久拒绝 → 页面全部 RPC（含开始配对）死锁。用户侧表象 =
「功能时好时坏 / 重启才恢复」一类玄学故障的合理候选源头。

修复：循环 peek 至见 `\r\n\r\n`（16KB 上限 + 3s 超时 fail-closed）。
装机版复测：0 拒绝、配对 23ms、清理期 RPC 5ms。cargo test（handshake 用例）3/3。

## 2. remote.session inject 报错定案（批次一备案项）

**完整堆栈**（probe-remote-session.cjs 实证，ui-home 复现）：
```
Error: cannot get property "remote.session" without inject
  at Object.get (cordis ReflectService trap)
  at Proxy.directoryFor (@deepseek-ai/dsh-client-ui-model-selection/lib/client.js:301)
```
机制：cordis 服务经 getTraceable 包装后「方法调用看见调用方的活动 context」——
`models.directoryFor()` 内 `this.ctx.remote.session` 实际在**调用方**（composer
slot inject 回调）的 ctx 上校验深路径 inject；该回调 ctx 未声明 remote.session，
且 home 未完成 boot 时 remote.session accessor 未就绪 → 抛错。
**这是内核 @deepseek-ai/* 边界内行为**（内核插件自身 inject 声明与 slot 回调
context 的组合问题），E2E 全过、不阻塞功能、页面后续渲染自愈。按「不碰内核」
纪律不修，备案待内核上游处理。
