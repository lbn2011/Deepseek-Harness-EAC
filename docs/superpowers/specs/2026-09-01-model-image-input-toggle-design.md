# 模型图片输入开关设计

## 背景

`@deepseek-ai/dsh-llm-pi-ai` 已支持通过模型配置中的 `input` 字段声明输入模态，并将其暴露为运行时的 `inputModalities`。当前模型配置界面没有直观入口，用户添加自定义视觉模型后容易被默认按纯文本模型处理，只能手动编辑 YAML 或借助 `picturereader` 绕过能力检查。

本功能只补充模型配置入口，不修改图片附件协议，也不依赖 `picturereader`。

## 交互设计

在“模型目录”表格的每个模型行中，将图片输入开关放在显示名称输入框和详情箭头之间：

```text
[模型 ID] [显示名称] [图片输入开关] [详情] [删除]
```

- 使用紧凑的二元开关，行内不重复显示文字标签。
- 悬停提示为“仅在模型及接口均支持图片输入时开启”。
- 开关必须保持模型行高度和现有详情、删除操作的位置稳定。
- 开关始终保留无障碍名称“图片输入”和工具提示。
- 关闭态使用透明背景、主题边框和次级文字色滑块；开启态才使用皮肤提供的语义强调色。
- 不写死颜色值，确保默认主题与内置皮肤都能保持清晰状态差异。

## 配置语义

开启某个模型的图片输入后，保存：

```yaml
- id: gpt-5.6-sol
  input:
    - text
    - image
```

关闭后删除该模型条目中的 `input` 字段，不写入 `input: [text]`。这样模型仍可继承已安装模型目录或提供商的 `defaultInput`，避免误关已知视觉模型的内置能力。

读取配置时：

- `input` 包含 `image`：开关显示为开启。
- `input` 不包含 `image` 或字段缺失：开关显示为关闭。
- 修改开关不得丢失模型条目中的 `name`、`contextWindow`、`maxTokens`、`reasoningEfforts` 或 `compat` 等字段。

## 数据流

1. 用户在模型行切换“图片输入”。
2. 设置表单更新当前模型条目的 `input` 字段。
3. 保存设置后由现有配置链路写入 `settings.yaml`。
4. `dsh-llm-pi-ai` 将模型的 `input` 转换为 `inputModalities`。
5. 会话控制器看到 `image` 能力后允许图片附件进入原生模型请求。

图片内容直接发送给所选模型后端，不经过 `picturereader`。

## 错误与兼容

- 默认保持关闭，不猜测未知模型是否支持图片。
- 开关只声明能力，不探测远端接口；网关实际不支持时，由提供商返回请求错误。
- 旧配置无需迁移，缺少 `input` 的模型继续沿用原有继承逻辑。
- 已手工配置 `input: [text, image]` 的用户升级后应看到开关已开启。
- 不修改提供商级 `defaultInput`，本功能仅控制单个模型。

## 验收

- 每个模型行都有独立图片输入开关。
- 开启并保存后生成 `input: [text, image]`。
- 关闭并保存后移除模型级 `input` 字段。
- 保存后重新打开设置，开关状态正确恢复。
- 开启模型可粘贴图片且不再出现 `MODEL_DOES_NOT_SUPPORT_IMAGES`。
- 关闭的未知模型仍被视为纯文本模型。
- 不安装或配置 `picturereader` 也能完成原生图片请求。
- 模型增删、详情展开、窄窗口布局和既有设置保存均无回归。
- 默认主题和内置皮肤下，关闭态不得呈现为已开启的强调色。
