# 对话输入区动态安全区设计

## 背景

DSH 会话页面将 `[data-composer-seat]` 作为底部 sticky 输入区放在
`[data-conversation-scroll]` 内。消息内容较长、输入框增高或附加状态区域展开时，
消息内容可能继续绘制到输入区下方，导致最后几行被遮挡；滚动停在中间位置时，
消息文字还会从输入区的透明部分后方透出。该问题在默认界面也会出现，皮肤只会
改变其可见程度，因此不能作为某个皮肤的专项修复。

## 目标

- 消息内容的可见底边始终停在输入区上方。
- 滚动到会话中间时，消息内容不能穿透输入区的透明区域。
- 输入区高度变化后自动更新安全距离，不使用固定像素猜测。
- 默认主题、内置皮肤和第三方皮肤使用同一修复。
- 不依赖 CSS Module 哈希类名，不修改用户配置或会话数据。
- 不改变 hero 居中、消息滚动、自动跟随和输入区 sticky 行为。

## 方案

扩展内置客户端插件 `dsh-viewport-lock`：

1. 使用稳定选择器定位 `[data-conversation-scroll]` 和其中的
   `[data-composer-seat]`。
2. 使用 `ResizeObserver` 监听输入区高度，并将测量值写入滚动容器上的
   `--dsh-composer-safe-height` CSS 变量。
3. 官方布局已经把 sticky 输入区作为滚动内容的正常流占位，不能再叠加一份等高
   `padding-bottom`，否则会产生双倍空白。动态高度只写入
   `scroll-padding-bottom`，保证程序化滚动的目标不会停在输入区后面，同时保留
   原生占位和手动滚动行为。
4. 输入区必须保持完全透明，不绘制任何背景遮罩。插件根据消息视图底边与输入区
   顶边的实时位置，为消息视图写入动态 `clip-path`，只裁掉进入输入区范围的消息
   像素，保留会话背景和皮肤背景。
5. 使用 `MutationObserver` 处理会话切换、热重载和输入区重新挂载；重复绑定必须
   幂等，旧观察器必须释放。
6. 输入区不存在时移除动态变量，恢复原生布局。

安全空间只作用于 active 会话内容，不改变 hero 首页和其他内部滚动面。

## 实现边界

- 修改 `dsh-viewport-lock` 的客户端实现，不直接修改 `@deepseek-ai/*` 安装包。
- 只使用公开、稳定的 `data-conversation-scroll`、`data-composer-seat` 和
  `data-slot="conversation.session"` 契约。
- 不写死主题颜色、输入区高度或侧栏宽度。
- 不为输入区写入背景色、渐变或模糊效果。
- 不将 Endfield、better-sidebar 或 Shikitor 作为运行依赖。

## 异常处理

- 浏览器不支持 `ResizeObserver` 时，以当前输入区高度完成一次测量，并在 DOM
  变化时重新测量。
- 找不到目标节点时保持无操作，不阻断页面启动。
- 插件卸载或 Cordis effect 释放时断开所有观察器并移除注入样式和动态变量。

## 验证

- DOM 测试：输入区初始高度会写入安全变量。
- DOM 测试：输入区高度变化会更新安全变量。
- DOM 测试：输入区保持透明，消息视图的裁切底边随输入区位置变化。
- DOM 测试：会话切换或输入区重挂载后重新绑定，且不会重复观察。
- DOM 测试：释放插件后移除变量和观察器。
- 运行时：默认主题长会话滚动到底，最后内容完整停在输入区上方。
- 运行时：Endfield 主题执行同一场景。
- 运行时：输入多行文本使输入区增高后，最后内容仍不被遮挡。
- 窄窗口：至少验证 980x640，不出现输入区、消息内容或操作按钮重叠。
