# better-sidebar 文件预览恢复设计

## 背景

EAC 当前内置 `dsh-better-sidebar 0.12.2`，但插件更新器可将 Profile 升级到
`0.15.2`。运行中的 `0.15.2` 在 EAC 内核上打开文件时可能抛出
`Cannot read properties of undefined (reading 'code')`。文件列表与预览复用同一个
编辑器标签，预览头部又没有返回入口，导致用户停留在错误页且无法恢复。

## 方案

EAC 维护一个受控的 `0.15.2` vendored 副本，并保留该版本已有功能：

1. 找出文件预览链路中依赖 rc.8 错误对象或模块契约的读取点，对缺失和畸形值做
   兼容归一化，确保预览失败时进入可读错误状态，而不是让 React 渲染树崩溃。
2. 在合并模式的文件预览头部最左侧增加返回图标按钮。若已有 Files 标签，则展开
   并激活它，再关闭当前预览标签；若没有，则把当前标签更新为
   `{ title: 'Files', path: '', meta: { ...meta, treeOpen: true } }`。两条路径都不
   创建新标签，也不丢失文件树宽度等元数据。
3. 扩展每标签 `RenderBoundary`，允许调用者传入恢复操作。文件预览崩溃时显示
   “返回文件列表”和“关闭标签”；根级边界仍只提供重试，避免根边界误关闭标签。
4. 将修复后的预构建 `lib/`、包元数据、许可证和必要运行文件同步到
   `dsh-desktop/assets/plugins/dsh-better-sidebar`。安装包继续不携带 `src/`。
5. 保持插件更新来源，但保证 EAC vendored 版本号不低于已知不兼容的 `0.15.2`，
   防止启动同步再次退回旧副本或被同版本未修复包覆盖。

## UI 行为

- 返回按钮使用插件现有左箭头图标和 `iconButton` 样式，放在路径输入框前。
- 只有当前标签存在文件路径时显示返回按钮。
- 按钮提供中文/英文 `aria-label` 和 tooltip，不增加文字按钮占用工具栏宽度。
- 返回后立即显示文件列表并展开文件树。
- 即使预览组件渲染崩溃，错误页仍可返回文件列表或关闭当前标签。

## 测试

- 先增加失败回归测试，锁定 vendored 产物包含返回动作、错误边界恢复动作和安全的
  错误对象读取。
- 运行 `npm run build` 与 better-sidebar 专项测试。
- 将修复后的插件同步到当前 `web-desktop` Profile，重启普通开发服务后冒烟：
  打开文本文件、返回文件列表、再次打开文件、模拟/触发预览失败并退出错误页。
- 本任务不运行完整资源装配、安装包或 Rust 构建。

## 非目标

- 不降级到 `0.12.2`。
- 不重构第三方插件源码。
- 不修改 Tauri/Rust 壳层。
- 不把本次改动混入已有的其他功能 PR。
