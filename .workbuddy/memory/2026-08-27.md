## CI 日志 89481668262 定位并修复 main.rs 编译错误（commit 063d355）

- 新 CI run（用户推送 2c89a69 合并树后触发）：**Linux fetch-runtime 已过**（fetch-npm 修复生效，命中 vendor/npm），两平台其余步骤全绿，唯一失败 = 步骤 13 `Tauri 壳测试`。
- 失败根因（真实 Rust 编译错误，非环境）：`tauri-shell/src/main.rs:99` 报 `unexpected closing delimiter: }`——合并上游 dba99e3b 时，上游 `resource_root()` 的闭合 `}` 与我方 184cc716 新增的同名函数叠在一起，多出一个 `}`。两平台同一报错（ubuntu: main.rs:99:1 / windows: main.rs:99:1）。

- 教训：**合并后必须验证 Rust 侧编译**——git 合并叠代码块会产生重复闭括号这类 parse 错误，typecheck（TS）覆盖不到。

## CI 日志 89501515165 定位并修复 nav_fence IPv6 bug（commit 0317e2c）

- 上轮 main.rs:99 修复后，cargo test 编译通过（Finished test profile in 1m43s），6 个 nav_fence 测试 5 过 1 挂：`allows_loopback_host_on_ws_port` 断言 `allowed("http://[::1]:19873/")` 失败（两平台同一测试）。
- 根因（本地实测 url crate 2.5.8）：`host_str()` 对 IPv6 返回**带方括号** `"[::1]"`（IPv4 返回 "127.0.0.1" 不带括号），原 `matches!(host_str(), Some("::1"))` 永远不匹配。
- 修复：改用 `url::Host` 类型化匹配（`Host::Ipv4/Ipv6` + `is_loopback()` + localhost 域名），Cargo.toml 加 `url = "2"` 直接依赖（lock 已锁 2.5.8）；顺手加 `[features] devtools = []` 消除 main.rs:445 unexpected_cfgs 警告。
- 本地验证突破：**用 rust-lld 作 linker 可绕开坏掉的 MSVC link.exe/lib.exe**（`RUSTFLAGS="-C linker=<repo>/tauri-shell/target/lld-link.exe"`），纯 Rust crate（url 等无 cc 依赖）可本地编译运行——urltest 复现修复逻辑 6/6 通过。tauri 依赖链（vswhom-sys build script 调 lib.exe）仍无法本地编译。
- CI 链路全景（ci.yml）：npm ci → fetch-runtime → typecheck → clippy → test:native → build TS → cargo test(当前) → npm test → build:native → tauri:build → NSIS 体积断言 → 上传 → linux-smoke 容器冒烟。tauri:build 与 linux-smoke 是剩余最大未知区。
- 教训：**合并产生的 bug 是一层层暴露的**——build script 校验 → 语法错误 → 运行时逻辑测试。每修一层下一层才可见；本地用 rust-lld 能验证纯 Rust 逻辑，但 tauri 依赖链编译只能靠 CI。
