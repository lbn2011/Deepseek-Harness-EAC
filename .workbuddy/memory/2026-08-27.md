## CI 日志 89481668262 定位并修复 main.rs 编译错误（commit 063d355）

- 新 CI run（用户推送 2c89a69 合并树后触发）：**Linux fetch-runtime 已过**（fetch-npm 修复生效，命中 vendor/npm），两平台其余步骤全绿，唯一失败 = 步骤 13 `Tauri 壳测试`。
- 失败根因（真实 Rust 编译错误，非环境）：`tauri-shell/src/main.rs:99` 报 `unexpected closing delimiter: }`——合并上游 dba99e3b 时，上游 `resource_root()` 的闭合 `}` 与我方 184cc716 新增的同名函数叠在一起，多出一个 `}`。两平台同一报错（ubuntu: main.rs:99:1 / windows: main.rs:99:1）。
- 这是**占位目录修复（69282ba）后的下一层**：之前 cargo test 卡在 build script（staged-resources 校验），编译没走到 main.rs；占位后前进到真正编译，暴露语法错误。
- 修复：删除多余 `}`。验证：`rustc --edition 2021 --emit=metadata src/main.rs` 无 parse 错误（144 error 全为裸 rustc 缺依赖的 E0432/E0433/E0308 级联）；本地 cargo check 仍被 MSVC lib.exe 0xC0000139 阻断（CI 无此问题，仅本地环境限制）。
- 教训：**合并后必须验证 Rust 侧编译**——git 合并叠代码块会产生重复闭括号这类 parse 错误，typecheck（TS）覆盖不到。
