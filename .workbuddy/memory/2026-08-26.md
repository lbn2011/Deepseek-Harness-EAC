## 运行时 boot 失败修复（commit 7f26ba8）

- 现象（用户报）：编译安装后启动「一次无限转圈、一次退出码 boot」。
- **根因**：`lib/proc.ts` 的 `nodeExe()`/`npmCli()` 在 `isPackaged()` 时切到 `resourcesPath()/node|npm`（Electron legacy-shell 布局）。但 Tauri sidecar 恒置 `DSH_RESOURCE_ROOT` → host-ctx `isPackaged()` 恒真，导致打包态与 Tauri 开发态都解析到不存在的 `<root>/node/node.exe`（真实在 `<root>/dsh-desktop/vendor/node/`）。
- 链路：`boot.start` → `startServer` → `nodeExe()` 不存在 → 抛「找不到内置 Node 运行时」→ Rust 壳导航 `/died?code=boot`（退出码 boot）；首启 `preBootSync` 慢时表现为加载页无限转圈。
- **修复**：`nodeExe()`/`npmCli()` 优先按 `__dirname` 相对定位（`<dsh-desktop>/vendor/node|npm`，覆盖开发态 + Tauri 打包态），存在即用；不存在才回退 legacy-shell `resourcesPath()/node|npm`（双宿主兼容）。
- 关键教训：**Rust 壳 `resolve_node()`（main.rs）与 TS 侧 `nodeExe()`（lib/proc.ts）两套路径解析必须一致**；Rust 侧找 `dsh-desktop/vendor/node` 是对的，TS 侧却用了 Electron 布局，两处没对齐才是本 bug。Tauri 迁移里「isPackaged 恒真」是隐蔽陷阱。
